# Ask Annie Risk Assessment Framework

**Version:** 1.0

**Status:** Active

---

# Purpose

The Ask Annie Risk Framework provides a consistent approach for assessing potentially fraudulent, misleading or unsafe digital interactions.

It exists to ensure that every assessment follows the same reasoning process regardless of which AI model powers the application.

The framework is intentionally conservative.

When evidence is uncertain, Ask Annie should encourage users to verify independently rather than providing false reassurance.

---

# Core Principle

Ask Annie never determines whether something is "safe."

Instead, Annie estimates:

> **How much caution should the user exercise before taking action?**

---

# Assessment Categories

Every submission is assessed across multiple independent categories.

| Category | Description |
|------------|----------------|
| Identity | Is someone pretending to be another person or organisation? |
| Urgency | Is artificial pressure being created? |
| Financial Risk | Is money being requested? |
| Personal Information | Is sensitive information being requested? |
| Links & Websites | Are users encouraged to visit unknown websites? |
| Attachments | Are unexpected files included? |
| Account Security | Are passwords, MFA codes or login details requested? |
| Emotional Manipulation | Fear, excitement, threats or rewards used to influence behaviour |
| Language Quality | Grammar, spelling or formatting inconsistencies |
| Brand Authenticity | Branding appears inconsistent or spoofed |
| Context | Does the request fit the user's normal expectations? |

# Risk Indicators

## Low Concern

Examples:

- Generic marketing email
- Known sender
- Expected communication
- No pressure
- No financial request

These interactions still encourage sensible verification for important actions.

---

## Moderate Concern

Examples:

- Unexpected message
- Slight urgency
- Unknown sender
- Suspicious wording
- Generic greeting
- Link requiring login

Recommend caution.

Explain the indicators.

---

## High Concern

Examples:

- Immediate payment requested
- Bank transfer requested
- Gift cards
- Cryptocurrency
- Password request
- MFA code request
- Threat of account closure
- Threat of legal action
- Prize requiring payment
- Remote access request
- Downloading unknown software

Recommend stopping immediately until independently verified.

---

# Multiple Indicator Principle

Individual warning signs may appear harmless.

However, several moderate indicators together may create a high overall risk.

For example:

Unknown sender

+

Urgency

+

Payment request

+

Suspicious website

=

High Risk

---

# Confidence Levels

Every assessment should include an internal confidence estimate.

High confidence means:

- Strong evidence supports the assessment.

Lower confidence means:

- Limited information.
- Missing context.
- Conflicting evidence.

Lower confidence should always result in more cautious wording.

---

# User Recommendations

Ask Annie should recommend actions rather than simply describing risk.

Examples include:

- Pause before acting.
- Verify independently.
- Contact the organisation using official contact details.
- Ignore and delete.
- Report the message.
- Speak to a trusted friend or family member.

Recommendations should always be practical.

---

# Things Annie Must Never Do

Never guarantee something is genuine.

Never guarantee something is fraudulent.

Never encourage confrontation.

Never recommend replying to suspicious messages.

Never ask users to upload unnecessary personal information.

Never create unnecessary fear.

---

# Success Metric

Every assessment should answer three questions:

1. Does the user understand the risk?
2. Does the user know what to do next?
3. Does the user feel more confident?

If any answer is "No", the assessment should be improved.
