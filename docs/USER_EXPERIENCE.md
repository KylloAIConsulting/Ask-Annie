# Ask Annie – User Experience (UX) Principles

**Version:** 1.0  
**Status:** Active

---

# Purpose

The purpose of this document is to define the experience users should have when interacting with Ask Annie.

Every design decision should reduce anxiety, increase confidence and encourage safer digital behaviour.

The experience is as important as the technology.

---

# User Promise

Every interaction with Ask Annie should leave the user feeling:

- Calmer
- Better informed
- More confident
- Able to decide what to do next

---

# Emotional Journey

## Before Opening Ask Annie

Users may feel:

- Worried
- Confused
- Pressured
- Embarrassed
- Unsure

---

## During Analysis

Users should feel:

- Reassured
- Listened to
- Supported
- Not judged

The interface should clearly communicate that analysis is in progress.

Avoid dramatic animations or alarming language.

---

## After Receiving Results

Users should feel:

- Relieved
- Empowered
- Confident
- In control

Every result must include a clear next step.

---

# Design Philosophy

Ask Annie should feel like speaking to a trusted friend who understands technology—not a cybersecurity expert lecturing the user.

---

# Interface Principles

## Keep It Simple

One task per screen.

Avoid clutter.

Avoid technical dashboards.

---

## Plain English

Replace technical terms with everyday language.

Example:

❌ Credential harvesting

✅ Someone may be trying to steal your login details.

---

## Calm Visual Design

Use:

- White space
- Large text
- Clear headings
- Soft colours
- Simple icons

Avoid:

- Flashing warnings
- Large red error screens
- Fear-inducing graphics

---

# User Flow

1. Open Ask Annie
2. Choose text or image
3. Submit
4. Analysis screen
5. Risk summary
6. Explanation
7. Recommended actions
8. Optional feedback

The journey should never exceed three taps before analysis begins.

---

# Accessibility

Every screen should support:

- Keyboard navigation
- Screen readers
- High contrast
- Large touch targets
- Zoom to 200%
- Colour-independent communication

---

# Language Rules

Always:

- Thank the user for checking.
- Explain why.
- Offer practical advice.
- Encourage independent verification.

Never:

- Shame the user.
- Create panic.
- Use excessive jargon.
- Assume technical knowledge.

---

# Success Metrics

The user should be able to answer "Yes" to these questions:

- Do I understand what Annie found?
- Do I know what to do next?
- Do I feel more confident?
- Would I use Ask Annie again?

---

# Product North Star

Every feature should answer one question:

> Does this help the user make a safer digital decision?

If the answer is no, the feature should be reconsidered.
