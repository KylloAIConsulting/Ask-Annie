Remaining SubmitScreen package requirements

1. File validation

Validate selected image files against the existing server contract:

Supported MIME types:
- image/jpeg
- image/png
- image/webp

Maximum size:
- 10 MB

Prefer a shared exported constant for the maximum upload size if one already exists in the server/shared code.

If no reusable shared constant exists, add one in the most appropriate shared schema/config file and update the relevant server validation to use it, avoiding duplicated magic numbers.

When an invalid file is selected:

Unsupported type:
“This image type is not supported. Please choose a JPG, PNG or WebP image.”

Oversized file:
“This image is too large. Please choose a smaller image.”

Requirements:
- Reject the invalid file.
- Do not pass it through the draft callback.
- Do not display it as the selected file.
- Associate the error with the native file input using aria-describedby.
- Use role="alert" for immediate announcement.
- Clear the file error after a valid file is subsequently selected.
- Ensure reselecting the same invalid file still triggers validation by safely resetting the native input value when appropriate.

2. Required-input validation

The current disabled primary-button behaviour should remain:

- Text mode: disabled when the message is blank or whitespace-only.
- Image mode: disabled when no valid image is selected.

Do not replace this with noisy validation-on-change.

As a defensive safeguard, the submit handler must also refuse to invoke onSubmit if the active draft is invalid, even if called programmatically.

No validation error should appear on the initial render.

3. Selected-file interaction

In image mode, after a valid file is selected, display:

- selected filename
- human-readable file size
- a “Remove image” button

“Remove image” must:

- clear the selected file
- clear the native file input
- return the primary button to its disabled state
- clear any related error
- be keyboard accessible
- have an accessible name that includes the filename, for example:
  aria-label="Remove selected image: example.png"

Do not make the entire upload area a button.

Do not add custom keyboard handling to a non-interactive container.

4. Draft callback integrity

Text submission must call onSubmit with:

{
  mode: 'text',
  text: string,
  context: string
}

Image submission must call onSubmit with:

{
  mode: 'image',
  file: File,
  context: string
}

Requirements:
- Trim only for validity checks.
- Preserve the user’s entered text and context exactly in the callback unless the existing approved implementation intentionally normalises them.
- Invalid drafts must never invoke onSubmit.
- SubmitScreen must not make any API request.
