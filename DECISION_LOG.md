# Ask Annie Decision Log

This document records significant product decisions and the reasoning behind them.

Unlike Architecture Decision Records (ADRs), this log captures product, UX and strategic decisions.

---

| Date | Decision | Reason |
|------|----------|--------|
| 28 Jul 2026 | Web-first MVP | Fastest route to user validation before mobile apps |
| 28 Jul 2026 | Mobile-responsive design | Most users will check suspicious messages on their phones |
| 28 Jul 2026 | No user accounts in MVP | Reduce friction and validate the core experience first |
| 28 Jul 2026 | No payment system in MVP | Focus entirely on solving the user problem before monetisation |
| 28 Jul 2026 | No database in MVP | Keep the architecture simple until persistence is genuinely needed |
| 28 Jul 2026 | AI responses must follow a fixed schema | Predictable frontend behaviour and model independence |
| 28 Jul 2026 | Annie should guide, not decide | Avoid false certainty and encourage independent verification |
| 28 Jul 2026 | No percentage scam score | Prevent users placing false confidence in arbitrary numbers |
| 28 Jul 2026 | Accessibility is a release requirement | Accessibility is a core product value, not an enhancement |
| 28 Jul 2026 | Privacy by default | Only process the minimum information required for each assessment |
| 28 Jul 2026 | Documentation before implementation | Establish clear product direction before generating code |
